# 🎧 TG Music Bot

Telegram-бот «мини-спотифай»: присылаешь ссылку — получаешь mp3 с обложкой и тегами.
Плюс поиск по названию, личная библиотека, избранное и рандомайзер.

Написан на **aiogram 3** + **yt-dlp**, хранит данные в **SQLite**, упакован в Docker.

---

## Возможности

| | |
|---|---|
| 🔗 **Скачивание по ссылке** | Кидаешь ссылку в чат — бот присылает mp3. Понимает YouTube / YouTube Music, SoundCloud, Bandcamp, VK-видео, прямые ссылки на медиа и всё остальное, что умеет yt-dlp |
| 🔍 **Поиск** | Просто напиши название — бот покажет до 5 вариантов с длительностью и источником, скачивание в один тап. `sc:` — искать только в SoundCloud |
| 📚 **Библиотека** | Всё скачанное сохраняется у пользователя: список, страницы, повторное прослушивание |
| ⭐ **Избранное** | Лайк под треком, отдельный список и «случайный из избранного» |
| 🎲 **Рандомайзер** | Случайный трек из библиотеки без повторов последних 10 прослушанных |
| ⚡ **Кэш Telegram** | После первой отправки сохраняется `file_id`: повторная выдача — мгновенная и без трафика |
| 🔒 **Понятный отказ для стримингов** | Ссылки Spotify / Apple Music / Deezer / Tidal бот распознаёт и объясняет, почему файла не будет, вместо непонятной ошибки |
| 🧹 **Чистые теги** | Из названий убирается «(Official Video)», «[Lyrics]» и прочий шум, исполнитель вытаскивается из «Artist — Title» или канала |
| 🛡 **Защита** | Антифлуд (N загрузок в минуту), белый список пользователей, лимит размера файла, удаление временных файлов |

## Быстрый старт (локально)

Нужен **Python 3.10+** и **ffmpeg** (без него не собрать mp3).

```bash
# Debian/Ubuntu
sudo apt install ffmpeg
# macOS
brew install ffmpeg
```

```bash
git clone <this-repo> && cd Arena-test
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# вставь в .env токен от @BotFather

python -m bot
```

В логах появится `Бот @your_bot запущен` — можно писать боту в Telegram.

## Запуск в Docker

```bash
cp .env.example .env   # BOT_TOKEN обязателен
docker compose up -d --build
docker compose logs -f
```

База и временные файлы лежат в `./data` (примонтирован томом).
Образ уже содержит ffmpeg.

## Запуск из GitHub (без своего сервера)

### Вариант 1. Прямо в GitHub Actions — для теста и демо

В репозитории есть workflow **Run bot** (`.github/workflows/run-bot.yml`).

1. **Settings → Secrets and variables → Actions → New repository secret**
   → имя `BOT_TOKEN`, значение — токен от @BotFather.
2. *(необязательно)* вкладка **Variables**: `ALLOWED_USERS` (ID через запятую)
   и `LOG_LEVEL`.
3. **Actions → Run bot → Run workflow**.

Через минуту бот оживёт и будет работать.

> ⚠️ GitHub показывает кнопку **Run workflow** и запускает `schedule` только для
> workflow из **ветки по умолчанию** (`main`). Пока изменения в отдельной ветке/PR —
> сначала смерджи их в `main`, иначе вкладка Actions будет пустой.

**Честные ограничения этого способа:**

| | |
|---|---|
| ⏱ Максимум 6 часов | Один запуск GitHub-hosted runner'а ограничен 6 часами, поэтому job сам завершается за 15 минут до лимита, а расписание (`cron`) поднимает его заново. В стыке — пауза ~15 минут, бот офлайн |
| 💾 Библиотека | SQLite тянется из кэша Actions (`best-effort`). Кэш может быть вытеснен, поэтому не рассчитывай на архив как на надёжное хранилище |
| 💸 Минуты | В **публичном** репозитории Actions бесплатны. В **приватном** — 2000 минут/месяц, это меньше двух суток непрерывной работы |
| 🚫 Не для 24/7 | GitHub не предназначен для постоянного хостинга ботов: расписание может задерживаться, а долгие job'ы — блокироваться. Для постоянной работы — вариант 2 |

Если бот уже был запущен локально, останови его: два polling-процесса
на одном токене дают `TelegramConflictError` (workflow защищён `concurrency`,
но локальный процесс он не видит).

### Вариант 2. Образ из GitHub Container Registry (рекомендую)

Workflow **Docker image** собирает образ при каждом пуше в `main` и публикует его в GHCR:

```
ghcr.io/<owner>/<repo>:latest
```

Запуск на любом сервере (VPS, домашний ПК, Raspberry Pi):

```bash
echo "<твой BOT_TOKEN>" > .env

docker run -d --name music-bot --restart unless-stopped \
  --env-file .env \
  -v "$PWD/data:/app/data" \
  ghcr.io/owner/repo:latest
```

Если пакет приватный — сначала `echo <PAT с правом read:packages> | docker login ghcr.io -u <username> --password-stdin`.

### Вариант 3. Хостинг, который деплоит сам

[Dockerfile](Dockerfile) в репозитории понимают Railway, Render, Fly.io, Koyeb,
Timeweb Cloud и любой другой PaaS: подключаешь GitHub-репозиторий, добавляешь
переменную `BOT_TOKEN` — платформа собирает и держит бота круглосуточно.
Бесплатные тарифы обычно засыпают при простое, поэтому для бота нужен
тариф с постоянной работой (или Oracle Cloud Always Free / дешёвый VPS).

## Настройки (`.env`)

Все параметры необязательные, кроме токена.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от [@BotFather](https://t.me/BotFather) |
| `DB_PATH` | `data/music.db` | Файл SQLite |
| `DOWNLOAD_DIR` | `data/downloads` | Каталог временных загрузок |
| `MAX_FILE_SIZE_MB` | `50` | Лимит файла (50 МБ для облачного Bot API, до 2000 МБ с локальным сервером) |
| `MAX_CONCURRENT_DOWNLOADS` | `3` | Сколько загрузок параллельно |
| `SEARCH_RESULTS` | `5` | Результатов поиска на запрос (1–10) |
| `RATE_LIMIT_COUNT` / `RATE_LIMIT_WINDOW` | `10` / `60` | Антифлуд: загрузок за окно в секундах |
| `AUDIO_QUALITY` | `192` | Битрейт mp3 в кбит/с |
| `COOKIES_FILE` | — | `cookies.txt` для источников, требующих входа |
| `PROXY` | — | Прокси для yt-dlp, например `http://user:pass@host:port` |
| `ALLOWED_USERS` | — | Telegram ID через запятую; пусто — бот открыт всем |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` |

## Как это работает

```
bot/
├── main.py              # сборка зависимостей, polling, команды, обработчик ошибок
├── config.py            # валидация .env, понятные сообщения об ошибках
├── db.py                # SQLite: треки, избранное, дедупликация, рандом
├── keyboards.py         # reply- и inline-клавиатуры
├── texts.py             # тексты и форматирование карточек
├── utils.py             # ссылки, названия, форматирование, безопасные имена
├── middlewares.py       # белый список пользователей
├── handlers/
│   ├── common.py        # /start, /help, меню, служебные callback-и
│   ├── music.py         # ссылки и поиск
│   ├── library.py       # библиотека, избранное, удаление, статистика
│   ├── random_track.py  # рандомайзер
│   └── shared.py        # общая обёртка «скачать + сообщить об ошибке»
└── services/
    ├── downloader.py    # yt-dlp: поиск, загрузка в mp3, человеческие ошибки
    ├── music.py         # сценарии: найти → скачать → сохранить → отправить
    ├── delivery.py      # отправка аудио и «живой» прогресс
    ├── library.py       # страницы и рандом без повторов
    ├── cache.py         # кэш результатов поиска (callback_data ≤ 64 байт)
    └── limiter.py       # антифлуд
```

Порядок обработки ссылки: `URL → нормализация (без tracking-параметров) → поиск в библиотеке → file_id из кэша → иначе скачивание → сохранение → отправка → сохранение file_id`.

## Ограничения и важные оговорки

- **Spotify по ссылке не скачивается.** У Spotify нет публичных mp3 — поток защищён DRM,
  и вытащить файл технически невозможно; бот честно об этом предупреждает. Бот работает с источниками, которые отдают аудио
  (YouTube, SoundCloud, Bandcamp, VK-видео, прямые файлы). По названию песни он найдёт её
  на доступных площадках — для этого и нужен поиск.
- **VK Music.** Большая часть музыкального каталога VK отдаётся только авторизованным
  пользователям. Анонимно бот качает то, что доступно публично (например, видео/аудио из
  открытых источников). Для приватного контента нужен `COOKIES_FILE` — но используй
  **только свой аккаунт** и только тот контент, на который у тебя есть права.
- **Лимит Telegram.** Обычный Bot API принимает файлы до 50 МБ. Хочешь больше —
  поднимай [локальный Bot API server](https://github.com/tdlib/telegram-bot-api)
  и увеличивай `MAX_FILE_SIZE_MB`.
- **Права.** Бот — инструмент, а не источник контента. Скачивай музыку для личного
  использования и не выкладывай чужой контент в публичный доступ. Ответственность за
  использование — на владельце бота.
- **Один инстанс.** Антифлуд и кэш поиска живут в памяти процесса; для нескольких
  реплик понадобится Redis.
- **GitHub Actions — не хостинг.** Запуск из Actions удобен для проверки, но бот там
  живёт циклами по 6 часов. Для круглосуточной работы используй Docker-образ
  (см. «Запуск из GitHub», вариант 2 или 3).

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `❌ BOT_TOKEN не задан` | Нет `.env` или токена в нём |
| `На сервере не установлен ffmpeg` | Поставь ffmpeg (в Docker-образе он есть) |
| `Источник требует авторизации` | Нужен `COOKIES_FILE` или другая ссылка |
| `Трек весит больше 50 МБ` | Ограничение Bot API — см. локальный сервер выше |
| `TelegramConflictError` в логах | Бот запущен дважды (второй процесс/polling + webhook) |
| Поиск пустой | Площадка может не отдавать результаты без cookies — попробуй `sc:` или прямую ссылку |
